# code78 / 0.5.57-test · 主页历史读取状态修复

## 根因

code77 的冷启动就绪路由把已配置账号导向 HOME，但原先“首次进入主页读取一次”的分支只有注释，没有发起比较。历史保持 null；共享历史组件把任何 null 都渲染成“正在读取存档历史…”。code75 的来源保护正确地禁止未核验存档上传/恢复，因而不能再借主页动作触发首次比较。

生产方法抽取执行的冷启动回归在修复前失败：已配置 HOME 的读取次数是 0，应为 1。现场反馈为历史区域文字持续、无居中加载蒙层、设置仍可打开，与未发起请求一致；不是已证实的网络死锁。翻译未改变状态枚举判断。

## 最小修改

- 已完成配置、已验证嵌入式桥接的冷启动 HOME 发起一次现有只读比较，不重复就绪检查。旋转重建的 HOME 也取得归属于新宿主的观察。
- 有待消费自动同步历史时不另起普通读取；就绪任务完成后消费已有自动历史。
- null 表示没有已验证的历史，不等于确认空。只有真实 archiveLoading 才显示已有读取文字/蒙层；失败沿用原错误区，确认空仍使用原空历史展示。
- 没有新增按钮或提示，没有恢复隐藏的设置入口。code75 来源有效性、完整图、上下文与过期确认保护不变。
- 读取仍由原来的 finally 结束 loading；游戏、账号、命名空间、页面、宿主失效或新一代读取均拒绝旧响应。没有清空真实数据或跳过远端完整性验证。

## Root 边界

Root 冷启动仍只查元数据，不新请求 su 权限、不导出游戏存档。现有 Root 运行时没有可保证不弹授权的权限探测 API；本次不扩展它。未取得 Root 历史时不再假显示读取，也不假造本地为空或解锁上传/恢复。

宿主的 RECHECK_SAVES 方法存在，但共享设置明确隐藏该行，不能把它当作可用用户入口。本轮保留可见的“设置向导 / 重新检查”流程；重新完成授权和连接后沿原流程读取。不能宣称所有 Root 冷启动自动历史问题已解决。

## 验证与限制

新增生产 Java 方法抽取执行测试覆盖冷启动、未完成配置、缺连接、连接失败、自动历史去重、Root 不导出、未验证桥接、旋转新观察；另以生产读取方法覆盖成功、确认空、BLOCKED、异常、取消、离页、销毁、切账号/游戏/命名空间和旧完成不覆盖新读取。

共享生产 Compose 离屏测试覆盖宽/窄布局，验证真实加载、失败/空闲 null、现有错误文字以及确认空历史展示。完整 Python、相关宿主脚本和 JVM/Android 编译结果见本轮证据目录。

后端每个 WebDAV 请求已有30秒上限，但整个历史完整性扫描没有总耗时上限；它可因多条慢请求耗时较长，本次没有实机证据证明它是报告根因，不改变扫描安全策略。云端测试不等于 Android 真机覆盖安装后验证。签名和发布由既有流程负责。
