# v5：三项连接信息原生 UI 复验

2026-10-09 UTC。结果：下述有限范围通过。使用本轮最终编译的桌面与核心 JAR，在 dot 云端 Linux 的两个新隔离 HOME/XDG_DATA_HOME/pdsync.workspace 中运行，只有本机 `127.0.0.1:8778` 演示服务和 demo 测试账号。没有用户电脑、真实凭据、生产 Cloudreve 或真实存档。

## 已实际验证

1. 首次打开只显示三个输入框：WebDAV 地址、用户名、密码；只有一个提交按钮“连接”，另有“取消”。没有档案名、测试连接、下一步或保存步骤。
2. 使用原生窗口边缘拖动缩短到最低高度：外框 550×520，客户区 540×486。三个字段、连接按钮与取消始终可见；后续认证错误也在同一屏可见，不需滚动寻找操作。
3. 点击取消后回主界面。核对本机没有写 config.json，服务没有收到任何请求，也没有创建应用目录。
4. 再打开，输入本机地址、用户名和故意错误的演示密码。点击一次连接得到 HTTP 401；地址、用户名和密码草稿保留，明确错误和“连接”按钮可见。此时仍没有写配置或创建远端目录。
5. 只更正密码后再次点击一次连接。服务根 `/dav-root/` 已存在，应用命名空间之前不存在。实际请求仅创建 `/dav-root/shattered/` 与 `/dav-root/shattered/default/` 两个空目录，并逐个 PROPFIND 回读验证；随后检查旧协议标记、读取完整档案列表。成功后直接进入主界面，没有第二次保存操作。
6. 成功配置只保存 endpoint、profile=default、username。没有密码、任意 saveRoot、手动版本或凭据保存标记。
7. 打开设置，更改用户名但不提交，通过标题栏关闭窗口。配置文件与关闭前逐字节相同，服务请求数保持 10，没有创建或删除其他目录；旧连接状态保持。
8. 主界面左栏能独立滚动，底部“查看云端已观察分支”可到达；本轮没有点击同步/恢复操作。
9. 第二个隔离环境预置旧配置 profile=`legacy-kept42`。重启显示地址与用户名、要求本次密码；取消后从“设置”进入相同三字段窗口。填写密码并点击连接后，仍使用 legacy-kept42，仅创建其缺失子目录并进入主界面；保存后 profile 未改成 default，也未出现额外的档案名字段。
10. 两个测试环境的游戏文件前后 SHA-256 全部一致。所有远端变更仅为 3 次 MKCOL：新连接 2 次，旧 profile 1 次；无 PUT、DELETE 或 MOVE，也没有创建用户输入的 WebDAV 根。两个同步器实例均通过普通关闭完整退出。
