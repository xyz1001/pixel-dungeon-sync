## 测试专用注入界面：业务流程通过

`InjectedUiSmoke` 仅在 testclasses，生产 desktop.jar 不含此入口或环境开关。测试窗口标题明确为 `v8 UI TEST · injected process guard`。这里只注入“已停止”状态，其余版本验证、稳定性、文件锁、冻结计划、真实HTTP与备份/恢复均走正常代码。以下结果不能替代生产进程检测验收。

1. 无基线启动后只读取云端，没有自动发布已有文件。
2. 点击上传生成并核验第一个不可变提交，显示设备名/短 ID、采集时间、文件修改时间和本机云端核验时间。UTC 元数据按桌面本地 PDT 显示。
3. 只修改合成存档文件，没有再次点击上传；静默后自动生成第二提交，父提交正确。
4. 选择首份快照并点击恢复；同一窗口确认，没有退出游戏/暂停同步勾选。先保留含第二份内容的备份，再恢复第一份字节；自动上传一个 kind=restore 的新提交，父提交仍为当前基线。
5. 恢复提交保留原设备与原采集时间，新操作准备时间独立。恢复后等待超过静默/采集窗口，没有因为自身写入继续生成重复提交。
6. 暂停后修改文件，超过静默窗口仍保持三个远端提交；手动上传可用，产生第四提交。
7. 重启仍暂停，设备 ID 保持；最终界面显示已上传的历史恢复来源，确认页展示所选设备、快照短 ID 和源时间。取消返回且内容/提交数不变。

最终为4个提交、4个对象、1份恢复前备份，无活动上传标记；见 ui-verification.json。业务阶段日志是闭合枚举，不含 URL/账号/密码/存档内容。07-final-injected-home.png 与08-final-injected-confirmation.png来自最终重构建后的冻结运行副本；其余 injected 截图为同轮业务检查。对应生产 JAR 哈希在 final-ui-runtime-sha256.txt。

## 环境故障与恢复

- 初次误将执行器 loopback 服务用于桌面网络空间，修正为桌面同一运行空间的测试服务。
- 初次界面使用正在被后续测试重构建的 JAR 路径，出现类加载错误；之后将已构建 JAR 复制为独立不可变运行副本，重新完成流程。不复用失败启动作为通过证据。
- 演示服务仅允许 demo profile，初始专用名称被 HTTP400 拒绝且输入保留；换为此隔离服务的公开 demo 空间后成功。
- CUA typeText 的 AT-SPI 绑定失效；正常截图坐标点击与受支持 pressKey 可用，公开 demo 密码用正常键盘输入。没有采用其他桌面自动化后门。
- 使用已有字体配置与进程级软件渲染；不是默认渲染路径、Windows/macOS、真实游戏载入或真实 Cloudreve 验证。
