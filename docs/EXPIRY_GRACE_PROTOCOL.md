# code82：客户端统一从服务器期限减一年

## 唯一输入与转换

沿用已发布79的登录 POST `/api/register`（`version=2, action=login`）和 Basic GET `/api/account/entitlement`。不新增公网路由、Bearer、token/profile 客户端调用或服务器部署前提。

原响应 `source=managed_ledger` 的 `expires_ms` 在本客户端中被明确解释为服务器保存期限。每个官方有限期账号，不论是否有标记、是否迁移，在 `ManagedAccountClient` 响应解析边界执行一次 UTC 日历 `minusYears(1)`，形成唯一真实服务期限 `Entitlement.expiresMs`。其后显示、缓存、手动/自动同步及每个DAV请求的期限校验直接使用此值，不能再减一年。数值0保持无限期；null仅在旧响应明确active=true时兼容无限期，否则是未知期限，不能授权同步，也不冒充已过期。

使用 UTC 规则保留时分秒与毫秒；例如：
- 2026-10-21T22:54:21.530Z → 2025-10-21T22:54:21.530Z
- 2024-02-29T12:34:56.789Z → 2023-02-28T12:34:56.789Z

不要求、读取或依赖旧81方案的grace标记。旧服务器`active`是按未减期限判断，不能用于客户端真实有效状态；本地以减后期限与可信服务器时间比较。认证失败、显式禁用账号、网络失败和无可信时间仍分别失败关闭，不把网络错误认定为过期。原服务认证本就拒绝禁用账号。

## 已登录状态与缓存

每个新的远程操作重新读取既有期限接口，每个DAV请求发送前检查同一租约。Android单调时钟包括深度睡眠；Desktop额外发现系统时间异常时保守拒绝，不据此宣称过期。重启不能用旧显示缓存授权。

持久化显示缓存升级格式，旧81及以前记录被视为不可用；不对含义不明确的旧缓存直接再减一年。新的记录只保存已转换的真实期限。纯本地恢复、归档、命名不因云端期限或网络故障被阻塞。

## 服务端源码与后续工作

82源码内server完整恢复为已发布79，原登录/认证及期限返回方式不变。撤回80/81的marker、真实期限输出和新公开接口方案，避免服务端已减一年后客户端再次减一年。本次不提供server部署包，不部署或修改真实账号。

后续注册/续期需要把服务器保存期限设为“真实期限+一年”，并保持对外expires_ms就是服务器保存期限。这项后续实现不包含在本次紧急客户端修复中；不应部署82附带的原79 server并假定其已实现加一年。此处不执行任何迁移、删除、清理或定时清理。
