# 存档管理原型验证（2026-10-08）

## 已完成实现

- 原生目录选择器、手动路径、目录与符号链接校验；完全空目录只用于恢复。
- 按实际目录、游戏、端点、档案、版本隔离的本地历史、pending、head；配置仅保存非秘密字段，凭据只在会话内。
- 整档案快照、当前远端下载、备份后恢复、恢复前备份可直接在历史中再次选择。
- 冲突双方先落盘，支持采用本地、备份后采用远端、暂不处理。远端变化不静默覆盖。
- 对 pending 的显式归档，不丢失历史；恢复期间阻止普通关闭；同目录操作使用进程间文件锁。
- 保留 GameAdapter 边界，不把 Shattered 二进制理解混入同步协议。

## 自动化验证

55 个 JVM 测试（原 37 + 新增 18）全部通过，failure/error/skipped 为 0。Python demo 服务回归 1 个通过。`:core:test :desktop:classes :desktop:writeCloudRuntimeClasspath` 构建成功。

新增测试覆盖非秘密配置、危险目录/链接/嵌套、空目标接入、整档案恢复及设置排除、备份再次恢复、重启与冻结 pending、端点/目录隔离、停止守卫、备份后外部文件变化、备份登记失败不改目标、冲突双方保留、本地选择新父版本、远端选择备份最新本地、选择期间远端变化、竞争发布 412、显式归档、损坏历史、版本不兼容及读取远端过期。

独立只读安全复核发现普通 Close 可中断破坏性恢复的问题，已修复为 busy 时拒绝关闭。同时将备份加入历史的步骤移至首次破坏性写入前，并新增失败注入测试。断电、强杀进程、外部并发写入仍不承诺安全。

## UI 与真实游戏验证

Linux 原生 UI 实际操作通过：启动/关闭/重启、配置保留及凭据清空、手动路径校验、选择器打开/取消/再打开/确认、同步确认取消后重试、远端读取、恢复确认取消后重试、冲突保留/取消/再打开/采用远端，以及延迟网络操作中普通 Close 被阻止。结果与截图见 `cloud-evidence/profile-ui-flow.json`。

官方 Shattered v4.0.2（内部版本 922）的隔离 `A → WebDAV → B → WebDAV → A` 真实往返通过，两次恢复后均实际读档、移动、保存并退出；真实排行榜、徽章与日记均验证。具体证据和边界见 [真实游戏验证](real-game-validation/REAL_GAME_VERIFICATION.md)。这轮版本字段仍是手动声明；随后版本自动识别改动应单独验证，不能借用此结论代替。

## 边界

人工“游戏已退出/其他同步已暂停”确认不等于自动检测。版本仍由用户声明。已有校验只能发现部分并发改动，未解决 TOCTOU 和断电事务。`bones.dat` 不在本轮文件白名单，恢复时保持目标原状；本轮不是整个游戏文件夹克隆。历史是本地已采集/读取的版本库，不枚举全部远端快照，也不补齐游戏有限排行榜之前的战绩。Windows/macOS（含 Intel）未测试；不能把 Linux 两个隔离 profile 当作两台真实跨平台设备。
