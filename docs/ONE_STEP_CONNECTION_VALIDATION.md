# 单步连接与自动应用目录（2026-10-09）

## 改动

用户现在只需输入地址、用户名、密码，再点击固定可见的“连接”。检查认证、准备应用目录和完整列举成功后，保存非敏感配置并直接进入主界面。移除测试/下一步/保存向导及档案名输入。错误与按钮不属于表单滚动区；错误区最多96dp并可独立滚动，短窗口也保留操作入口。失败保留输入，操作中阻止重复提交、改动字段和关闭造成的旧回调写入。

新连接使用适配器自动空间（首个游戏为default）；原配置和显式测试配置的profile原值保留。它是内部同步命名空间，不是游戏角色名。游戏JAR在主界面单独选择，仅更新目标版本字段；不把版本选择混入首次连接。

新连接密码只留在会话。只沿用同一既有地址/账号已启用的系统安全存储偏好；改换身份会清除继承密码和保存偏好。没有明文后备，没有新的隐式凭据持久化许可。

## 自动创建的边界

仅显式ConnectionSetup.connect()调用ensureNamespace；testConnection及自动重连检查保持只读。

1. 用户配置的DAV根必须已经存在，先Depth:0确认精确href与集合类型。
2. 只处理根下的游戏和profile两级，每一级先查是否存在，404才MKCOL。
3. MKCOL201、405或响应丢失都必须再Depth:0确认集合。405不是成功凭据，同名普通文件拒绝。
4. 根缺失、401、403、409、重定向、XML/href异常与网络问题分别失败，不向上递归创建或跨根操作。最多7个命名空间请求；不盲重试MKCOL，也阻断HTTP库在503等状态下的自动重放。
5. 每个请求前检查取消/旧版本状态；已经创建的空文件夹会保留，不用DELETE“回滚”。连接不上传存档。

原始URL在HttpUrl标准化前就拒绝点路径、反斜线、编码分隔符和双重编码，防止用户配置的根边界被悄悄改写。

## 范围与限制

所有开发和自动化验证仍在云端；未改用户Linux目录、未读取或复用用户输入密码、未对真实用户服务发认证/写入请求。用户上一轮实际HTTP错误码没有观察到，不能将其称为已确认404。

追加式协议、备份/恢复、DAG和游戏数据格式未改。本轮不重新宣称v4的实际游戏截图属于新界面；新的有限原生UI复验单独记录。既有Cloudreve实机、跨平台、系统凭据服务成功存取、断电和并发写入限制继续成立。
