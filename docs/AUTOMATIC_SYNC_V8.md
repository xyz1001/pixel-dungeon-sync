# v8 自动上传与双按钮界面

2026-10-09，云端 Linux 开发。此文说明行为和限制；最终测试证据另列。不是跨平台验收或真实存档唯一备份承诺。

## 用户流程

- 主页面只有“上传”“恢复”两个操作按钮。设置为次级导航，含暂停自动上传、选择官方 JAR、连接设置、检查/归档中断操作。
- 首次连接仍只有 WebDAV 地址、用户名、密码和一个连接动作，同一个根窗口内导航。保留既有、明确启用的系统安全密码记忆；没有新增明文保存或默认密码。
- 自动行为是上传本地变化以及只读获取云端分支，绝不自动下载覆盖本地。
- 每秒内容观察，变化或已观察到游戏退出后先静默 2.5 秒，再进行核心独立的 2 秒稳定性检查。文件变化仍在继续时等待。当前账户游戏运行、相关进程信息未知或无可信目标 JAR 时停止上传/恢复。
- 设置暂停后不自动发布。手动上传仍可继续冻结的待上传计划。已开始的原子业务操作会完成；暂停不会中断正在备份/恢复的文件写入。
- 无已建立基线的新档案，启动只观察，已有存档须先点击一次上传；之后的新变化/游戏退出可触发。已有验证基线则比较启动内容，补传同步器关闭期间的变化。空目录只用于恢复，不发布空快照。
- 云端分支在连接后和空闲时每分钟读取；显示的是已观察分支，没有“全局最新”承诺。多分支暂停自动发布，用户点击恢复进入显式整份选择。
- 恢复不要求退出游戏/暂停云同步勾选。仍需确认替换范围，自动检查进程、实际存档版本、原始 ZIP、备份、文件集合和属性。普通云端恢复保持脏基线阻止；历史恢复创建新提交并自动重试上传，暂停时可手动上传。

## 队列和竞争边界

首次网络请求之前就持久化冻结 ZIP、独立提交 ID、原始父基线和元数据。断网首次尝试也留下可跨重启的待上传计划。5 秒起指数退避，最多 120 秒；重试只使用同键同字节。401/403 进入重连，完整性/非法路径问题停止自动重试并可见提示。游戏重启/文件未稳定属于可恢复等待，不被当成永久失败。

主 UI 的单一业务忙碌守卫覆盖手动上传、自动发布、恢复、冲突选择和云端读取。只读观察不争用文件变更锁，观察后重新检查页面、会话、连接及忙碌状态；业务方法仍持有真实目录的 OS 文件锁，并重新校验。设置/确认页面期间不启动背景操作。恢复后的观察基线来自真正应用的源文件哈希，而非事后读取的活动文件，避免吞掉恢复刚完成后的新变化。只重试已有恢复计划，不因自己的文件替换生成无限新提交。

进程检测只针对当前 OS 账号的可见进程。明确属于其他账号的进程跳过；缺少所有者并不自动安全，候选 Java/游戏进程身份不清仍失败关闭。所选官方 JAR 路径、Java 启动主类与参数向量用于判断。改名/复制的未识别 JAR、相对路径无法解析、argfile、部分参数不可见都会阻止，不能猜测为未运行。普通不同 Java 主类与明确非游戏命令可排除。原生安装包只作疑似识别并阻止，尚不支持可靠定位。Windows/macOS 的模型测试不等于原生进程检查成功。

稳定性覆盖文件内容、大小、mtime、fileKey 和局目录成员；备份捕获后保留确切指纹，在第一次删除前再核对。该核对在替换 try/rollback 区域之外，因此尚未写入时发现变化只停止，不错误地回滚外部新内容。进程检查与两次观察之间仍存在 TOCTOU；不能锁住游戏、其他账号、Steam Cloud 或远端设备。没有新增断电事务保证。

## 时间和来源

详见 [元数据格式](SNAPSHOT_METADATA.md)。设备名是经过限制和控制字符清理的主机名，并显示稳定随机设备短 ID；相同名称设备不会成为同一同步身份。元数据随快照上传，主页面明确提示。原始游戏字节不修改。采集时间、文件 mtime、提交准备时间和本机观察成功时间分别记录；后者不是服务器提交时间，也不用于判断分支优先级。UTC 保存，本地时区显示。旧条目保留未知，恢复和冲突选择保留源快照原身份，新操作另记发布设备。

新客户端可读旧条目；旧严格 v7 客户端不能读取带新字段的条目，应协调升级，不能混用并宣称向前兼容。
