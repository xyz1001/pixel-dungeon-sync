# 追加式 WebDAV 同步协议 v2

本轮目标是兼容不执行 `If-Match` / `If-None-Match` 条件覆盖的 WebDAV 服务。桌面与隔离 CLI 演示改用本协议；不修改 Cloudreve 服务端。旧 `Store` / `WebDav` / `Sync` 代码仅保留给历史兼容测试，不是新桌面的发布路径。

## 文件与身份

用户配置的 WebDAV 根必须已经存在。显式“连接”先验证根，再按需创建仅有的 `<game>/<profile>/` 两级应用集合并回读验证；普通同步和自动探测不创建目录。首次空间由适配器自动指定，原有配置ID不变。集合内仅新增两个平面文件类型：

- `pdsync-v2-object-<随机 UUIDv4>.zip`
- `pdsync-v2-commit-<独立随机 UUIDv4>.json`

一次提交记录协议号 2、提交 ID、父提交 ID 列表、完整快照元数据、ZIP 字节数与操作种类。快照元数据仍使用严格的 schema 1 归档格式，其 `parent` 固定为 null；v2 的祖先关系只来自外层 `parents`。ZIP 身份与提交身份分别产生，均不由设备名、账号、时钟或时间戳决定。

没有共享权威 `head` / `latest`，没有远端锁文件、MOVE 锁、条件覆盖要求或自动远端 GC。读取 ETag 不参与身份、完整性或排他性判断。

## 发布和重试

1. 在本地 profile 的操作系统文件锁内，冻结父提交列表、两个 ID、精确 JSON 字节、ZIP 内容和摘要，原子保存计划，再登记活动计划。
2. 完整发现并验证已知远端 DAG；普通提交只能引用实际本地基线的一个父提交，新设备可创建独立根分支。不能把刚看见的所有 tips 当作自己的父版本。
3. 回读对象键。如果不存在才 PUT；如果已存在，必须与冻结字节逐字节相同。PUT 后回读 ZIP，确认完整长度/字节内容。
4. ZIP 已验证后，才对独立提交键执行相同的读取、写入、完整回读。
5. 请求成功但响应丢失时，回读确认相同字节即可收敛。重启重试使用同一计划，不重新打包、改父版本或替换其字节。
6. 最后再发现 DAG、确认发布提交可用，才记录本地基线、移除活动标记。当前目录若已另有修改，仍与基线内容不同，不会因此变成干净。

已有同名内容不同时，客户端停止，绝不尝试覆盖。远端 ZIP 尚未被任何提交引用时是无害孤儿。

### 必须了解的故障边界

若服务将某个 PUT 的前半部分永久写在原键，客户端无法既保证“同键同字节”又无条件修复该键。对错误或截断内容的重试会停止。若不完整的提交文件已被发现，该 ID 会持久保留为未解决项；随后从列表中消失也不会将档案误判为空。

目前没有自动修复、删档或远端清理功能。应保留本地冻结计划、历史与原远端资料，由用户明确处理服务端问题，或者在停止所有旧/新客户端后选择一个新的空远端档案，再显式使用已经核验的本地存档。不能通过清除本地状态来声称问题已恢复，也不能自动删除损坏提交来解除阻塞。

## 发现、祖先和分支

- PROPFIND `Depth: 1` 读取整个集合。WebDAV 没有通用分页标准；若服务返回 HTTP `Link: ...; rel="next"`，跟随同源、同一集合的下一页直到结束。
- 拒绝跨源、跨路径、用户信息、片段、路径穿越、无效 UUID、循环分页、可见截断与不支持的分页扩展。不在对象请求中复用分页查询串。
- 发现过的提交 ID 与有效结构的原始 manifest 字节都持久保留；新列表漏掉旧 ID 时仍直接读取。祖先未在列表出现时，也按精确 ID 直接读取。
- 只有结构严格合法、ZIP 大小/哈希/每文件内容验证成功且全部祖先完整可用的提交，才进入有效 DAG。缺失、损坏、无效父关系或环路保持 pending；没有“跳过坏提交然后当作空根”的路径。
- 已记住的同一 manifest ID 如果字节改变，即视为完整性故障。远端对象每次重新校验。
- tips 由祖先关系计算；时间戳、返回顺序或设备名均不能选出胜者。单一观测 tip 仍只是当前观测，不能保证没有尚未列出的并发分支。后到的同胞分支仍会被展示为冲突。

每次扫描上限为 10,000 个提交、10,000 页以及 256 MiB 累计 manifest/ZIP 工作预算（预留声明大小，并对实际返回的额外字节补计；错误声明最多允许单个有界 ZIP 的读入超额，随后立即停止）。每页 XML 2 MiB，单个 manifest 2 MiB，ZIP 64 MiB，文件数 4,096，单次解析父版本至多 64 个。超过上限会明确停止，绝不默默接受半份历史。当前实现重新读取全部已知历史的 ZIP，长历史开销较大；没有以缓存跳过远端完整性检查的优化。达到上限需用户另行规划归档/新档案，不会自动 GC。

## 本地基线、恢复和选择

- v2 基线存于独立状态目录，绝不将旧版 `head.txt` 自动当成 v2 基线。已有基线标记但基线文件丢失时，停止，不初始化新根。
- 普通云端恢复只允许空的新目标，或内容仍匹配已验证基线且目标为该基线后代的目标。脏存档、缺少基线但已有内容、丢失/损坏基线都不能被普通远端读取覆盖。
- 本地历史恢复会先备份实际当前目录并校验游戏版本，在实际安装成功后留下一个新的、引用实际基线的 restore 计划。之后上传创建新提交，不回退或改写远端历史。
- 多分支必须显式选择整份快照。选择在已展示的父分支上建立新的多父 resolution 提交；原分支仍保留，不合并二进制存档。选择期间本地或已观测远端分支改变时，必须刷新选择。
- 操作系统文件锁保护同一应用状态目录内、指向同一真实本地存档根的并发操作；独立安装若使用不同状态目录，不共享此锁。这是本地进程协调，不是远端普通文件锁，仍须人工确认没有其他写入者。
- 既有 ZIP 路径校验、符号链接拒绝、全档案备份、写入失败回滚、版本识别、降级阻止和 Steam Cloud/游戏退出人工确认继续生效。恢复后额外回读文件摘要确认安装结果。

## 旧协议迁移与兼容

发现 `head.json`（包括损坏内容）即阻止新协议自动写入该集合。连接测试会明确显示旧协议边界。不修改、不覆盖、不删除旧 head、旧 ZIP 或旧 manifest；不把条件 PUT 当成迁移锁；不在旧、新发布协议之间静默回退。

本轮不提供自动原地导入。安全路径是用户先停用所有旧客户端并备份旧资料，明确选择新的空远端档案，再使用已核验的本地存档作为新根。已有旧本地历史保留可读；旧待上传队列需要显式归档，不能自动发送为 v2。旧客户端与 v2 客户端同时向同一集合写入不受支持。

## 信任和验证范围

这是遵守协议的客户端在可信 WebDAV 存储上的冲突保留机制，不是服务端强制不可变存储。GET 可能陈旧；没有 CAS 的随机键首次写入仍存在理论碰撞/陈旧读取竞态。独立 UUIDv4 使正常客户端意外同键极低；不能据此承诺对恶意服务端或任意其他写入者的原子保护。

ZIP 哈希和已见 manifest 字节校验可发现损坏/已见历史改写，但不为首次读到的历史提供密码学身份认证。服务端若把 manifest 与 ZIP 一并伪造，客户端不能证明其来源。没有签名、恶意服务端容错、远端完整性证明或全局最新保证。

恢复应用前写入 apply-required 标记；操作若中断，普通上传/恢复停止，需用户检查本地和备份后明确归档。它是进程重启保护，不是断电事务：本地写入没有 fsync 保证。既有并发路径替换 TOCTOU 与断电恢复事务仍不是已解决问题；保留独立备份，勿将唯一存档托付给此原型。此轮不连接真实 Cloudreve、不使用凭据、不远端部署。Windows、Linux、macOS（含 Intel）保留代码路径；仅实际执行的平台可以称已验证，Android 尚未实现。

实际测试命令、数量、构建与 UI 条件见同目录 `APPEND_ONLY_VALIDATION.md`。
