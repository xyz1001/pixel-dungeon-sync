# 三步首次引导（v10）

2026-10-09，云端 Linux。基于本地 Git v9 `b9521c943e146ca3b2fe879b4274e6e1d101a0ae` 继续开发，保留父历史。没有操作用户本机正在运行的 v9、真实服务或凭据。

## 界面流程

1. **找到游戏与本机存档**。只扫描已验证的系统默认存档位置和有界、平层安装候选目录。展示扫描到的可信游戏、版本和路径；没有可信结果、多个结果或扫描不完整时由用户明确选择。标准 JAR 文件选择器是唯一保留的系统选择窗口，应用页面本身仍在一个主窗口。手动选择也只读取，不运行游戏。
2. **连接云端**。当前仍只有 WebDAV 地址、用户名、密码和一个“连接”按钮。显式连接仅按需准备原有应用的两级目录，并保留旧 profile。未加入下载游戏、付费套餐或自建服务售卖；未来可在本步骤扩展服务选择。新账号不继承其他账号的密码保存授权，沿用系统安全存储规则。
3. **比较并选择**。完整枚举并验证追加式 DAG、所有祖先、ZIP 和内容校验和，等待本机存档稳定，再显示本机与云端的设备、时间、实际存档版本与分支。未完成安全比较不显示“云端为空”，也不释放自动上传。

找不到默认存档目录时，扫描本身不创建目录。第一步“继续”明确告知会仅准备该空默认目录以供后续恢复；不生成游戏存档、不会改选其他位置。检查并拒绝符号链接、错误路径类型及不安全祖先。双方都空时引导用户进入游戏创建进度；用户明确进入主页后仅观察未来变化，不制造同步基线、不上传空快照。将刚核验的空内容作为本次会话观察起点，第一份新存档立即出现也不会被当作启动时原有内容。首次真实上传前重启同步器会重新进行第三步比较，包括在同步器关闭期间创建的新存档。

## 比较与动作边界

- **只有本机**：显式上传。网络前冻结原快照；失败后明确重试仍使用同一计划。
- **只有云端**：选择已验证快照，明确恢复。单一分支对真正空的目标使用既有恢复；多个分支必须明确选择并保留全部父版本。
- **内容一致，已有相同同步基线**：重新核验当前证明后直接进入主页，不写新提交。
- **内容一致，但新设备没有基线／基线为祖先**：明确“采用云端关联”，只关联精确核验过的提交，不写存档、不发布无关根。仅相同哈希不作为自动猜测祖先的依据。
- **内容不同／多个分支**：不会按设备时间选胜者。“上传本机，保留云端分支”保留双方；选择恢复时，非空且未关联或有本机变化的内容先作为自身分支保留，再按用户所选整份云端进度解决。后来出现的新分支返回重新选择，不能悄悄纳入确认。已有本机变化和远端分叉不会自动覆盖。
- **待上传／上次恢复未确认／旧协议／完整性失败／权限或进程状态未知**：阻止新决定。完整 DAG 已核验的冻结上传可显式重试；其他中断操作在原设置页检查并明确归档后重新比较。

比较证明绑定当前 session，内部集合只读，动作在原档案 OS 锁下重验本机内容和文件属性、基线、待上传身份以及完整云端图。按钮打开期间的文件变化、触摸、远端新分支、祖先消失、同 ID 改写或换 session 都会拒绝旧选择。没有把未知状态转成空状态的降级路径。

仅关联相同字节或选择内容相同的分支不做“写入前兼容性”阻挡，因为不恢复字节；真正替换存档仍使用现有可信游戏和存档版本兼容性检查。全局记录、非活动槽位不能被伪装成有已知活跃存档版本。

## 生命周期与兼容

配置新增非秘密枚举 `onboardingProgress`：旧配置未带该字段时为 `LEGACY`，新连接为 `PENDING`，明确完成为 `COMPLETE`，未决定的“稍后处理”为 `DEFERRED`。旧 v9 的可信目标和已存在真实基线允许直接继续原设置；没有基线的旧配置只补做比较，不重跑完整选择。

自动上传的准入独立于当前页面：必须完成引导、没有正在重开的引导、已经成功完整检查云端，才可运行。取消、设置返回、身份修改、目标更换、重新打开和重启不会跳过此门槛。云端检查失败继续暂停，按有界间隔重试。DEFERRED 返回主页时明确显示暂停，上传／恢复按钮重新进入比较。

第一页扫描和第二页连接不采集或上传存档。比较可更新本机已观察历史缓存，但不改写存档。成功上传、恢复、明确关联或双方空的明确决定后才能结束；“稍后处理”不伪造已同步基线。
