# 阶段一需求、验收与门槛

目标平台 Windows x64、Linux x64、macOS Intel x64 和 Apple Silicon arm64；后两者都必须构建与运行，不允许仅 CI 配置宣称支持。客户端免费，可选未来付费 WebDAV 托管及自定义服务，无强制注册。

目标安装渠道 Steam 与官方独立版；其他打包渠道提供手动路径并标记未验证。本轮只有隔离演示路径，渠道发现尚未实现，不能宣称首期产品已完成。

## 已实现的核心验收

1. 同一快照包含完整 gameN 及全局记录；往返与设置保留。
2. 上传中断/远端校验失败时不发布清单；认证失败明确报错。
3. 强 ETag 条件更新保护清单；412 不推进本地成功版本。
4. 离线分叉保留快照、拒绝静默覆盖；显式选择 UI 待做。
5. 恢复验证归档，备份持久记录，失败回滚；游戏运行/版本不兼容拒绝恢复。
6. 删除的局不从旧文件恢复；快照全量替换 gameN 与持久记录。
7. 安装路径以实际目录去重。

## 下一步（真实存档使用前）

- 从官方 Shattered 源码核实 Windows/Linux/macOS 的 Steam/独立版路径、文件格式/版本元数据及启动参数；手动选路径与别名去重接入 UI。
- 实现各平台进程/文件占用检查、快照采集前后稳定性检查；用户确认不能替代可靠运行检测。
- 冲突双方可查看和显式选择，持久版本日志、历史下载、恢复与删除确认。保留父链不可变清单，远端孤儿回收策略。
- 恢复事务日志、断电恢复、备份耐久写入、磁盘满及回滚再失败的救援流程。当前同步只支持单进程，无多客户端本地锁。
- 真正死亡/删除游戏事件验证、离线旧端必须冲突而不能复活。全局记录必须始终随选定快照一起恢复。
- WebDAV 服务能力探测（条件写语义/强 ETag）、缺失集合创建、安全凭据存储、超时/重试、有限下载大小；远端目前信任 HTTPS/隔离服务，不支持任意巨大下载。
- Steam Cloud 并发实验和告警，绝不擅自关闭 Steam Cloud。
- 四平台实机编译、安装包、启动/退出和实际游戏存读闭环；其他渠道标注未验证。macOS Intel 为发布阻断门槛，若 Compose 无法通过，报告后再决定替换 UI。
- Android 宿主可行性单独研究，不实现 iOS。

当前验收是“隔离原型可审查”，不是“真实用户数据同步工具可发布”。
