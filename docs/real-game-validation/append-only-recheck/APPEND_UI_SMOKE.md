2026-10-09 UTC，结果：下列有限范围通过。使用最终已编译 `desktop.jar`（SHA-256 `5b37f60c919bb7ffea1530f00129950dce1fceea75d1678267bb4eefb5ad1ea6`），dot 云端 Linux 的独立 HOME、XDG_DATA_HOME、pdsync.workspace。没有访问用户电脑或真实凭据。

## 通过的实际 UI 步骤

- 无 config 首次启动显示中文两步连接向导；默认存档位置只读，来自隔离 XDG 路径。
- 点击“取消”返回主界面；文件检查确认没有 config.json 写入。
- 再次打开向导，输入本机 loopback 地址和公开 demo 演示账号；未勾选保存密码。
- 向导内滚动后可看到并点击“测试连接”。服务日志确认仅 GET 旧标记和完整 PROPFIND；成功后“下一步”启用。
- 到第二步时尚未保存配置；点击“上一步”后地址、用户名、遮蔽的密码和档案名保留。再次前进并“保存并开始”进入主界面。
- 主界面显示云端已连接、game1:922、一个进行中存档及没有目标 JAR 的说明。
- 点击“查看云端已观察分支”，读取专门复制的三个提交/三个 ZIP，显示两个并发 tips；每条以提交 ID、逐局版本、文件数及快照 ID 区分。底部明确提示这是已观察分支，普通恢复需单一分支/干净基线。
- 选择其中一个分支后，恢复按钮禁用，明确提示先选目标游戏 JAR，不能从存档推断已安装版本。
- 结束后通过普通关闭窗口退出，窗口清单确认同步器关闭。

## 数据核对

界面只读两个旧游戏分支的副本，和主游戏验证的远端目录隔离。前后逐文件 SHA-256 相同：隔离游戏目录未改变，远端 6 个文件未改变；服务日志没有 PUT。新 config.json 仅有 endpoint/profile/username，没有密码、saveRoot 或假定游戏版本。本次没有调用系统凭据保存。
